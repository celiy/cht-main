Seguindo a mesma ideia de uma table com props em cada componente no docs, incluir uma table para slots. Achar um jeito de fazer o componente exportar algo que define os slots juntamente com suas descrições
    Resumo, tratando slots como props: declarados, tipados e consultáveis.

    1. Declarar os slots com defineSlots (tipo, como o defineProps)

    <script setup lang="ts">
    defineSlots<{
    default?: () => any;
    footer?: (props: { close: () => void }) => any;
    }>();
    </script>
    2. Expor a lista em tempo de execução, como uma constante ao lado do componente

    export const SLOT_NAMES = ["default", "footer"] as const;
    Como defineSlots é só tipo, essa constante é a única forma de ter a lista em runtime. Ela precisa ser mantida em sincronia com o defineSlots.

    3. Consultar o que o pai passou, sem depender de reatividade

    import { useSlots } from "vue";

    const slots = useSlots();
    const hasSlot = (name: string) => !!slots[name];

    4. Opcional: expor pelo componente para quem usa ref

    defineExpose({ slotNames: SLOT_NAMES });
    Pontos de atenção

    hasSlot deve ser chamado no template ou na função de render, não em computed.
    Para a documentação do cht-design-system, a fonte da verdade é o defineSlots. A constante serve só se a página de docs precisar da lista em runtime.
    Como o defineProps, mantenha os nomes em inglês no código e os textos de UI em português.
